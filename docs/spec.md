# 와글(WAGLE) 서비스 설계서

작성: SON · 2026-10-18 · 원본: claude.ai 설계서 문서에서 내보냄

## 개요와 설계 원칙

치지직·SOOP·유튜브 등 각 플랫폼의 **공식 API에서 직접 수집**해, 시청자 통계 기능 전부를 무료로 여는 독자 서비스를 만든다. viewership.softc.one의 내부 API, 데이터, 화면 구성은 쓰지 않는다.

그 사이트의 숫자도 결국 각 플랫폼 원천에서 나온 것이다. 원천에서 직접 받으면 그 사이트를 분석할 이유가 없고, 법적 리스크도 사라진다. 참고로 이 사이트는 robots.txt로 자동 접근을 막고 있다.

| 구분 | 하는 것 | 하지 않는 것 |
| --- | --- | --- |
| 데이터 | 플랫폼 공식 Open API로 직접 수집, 자체 DB에 시계열 축적 | softc 사이트의 내부 API 호출, 화면 크롤링, 유료 구간 우회 |
| 기능 | 동종 서비스의 일반적 기능(랭킹, 추이, 카테고리 통계)을 자체 설계 | softc의 화면 배치, 문구, 디자인, 지표 명칭 그대로 복제 |
| 수익 | 모든 지표 무료, 비용은 광고·후원·API 제공으로 충당 | 타 사이트 유료 데이터를 받아 무료 재배포 |

"유료 정보를 무료로"는 **우리가 직접 모은 데이터를 무료로 공개하는 사업 선택**으로 설계한다. 이는 정상적인 경쟁이다. 반면 다른 사이트의 유료 데이터를 가져다 푸는 것은 데이터베이스 제작자 권리와 부정경쟁방지법 위반 소지가 크다.

## 데이터 소스

1차 소스는 치지직 공식 Open API와 유튜브 Data API다. SOOP은 공식 API가 파트너 전용으로 알려져 있어 **제휴 신청이 선행 과제**다.

| 플랫폼 | 소스 | 인증 | 얻을 수 있는 지표 | 사용 등급 |
| --- | --- | --- | --- | --- |
| 치지직 | Open API (openapi.chzzk.naver.com) | 개발자센터 Client ID/Secret | 라이브 목록(동시 시청자, 제목, 카테고리, 시작 시각), 채널 정보, 카테고리 검색 | 기본 사용 |
| 치지직 | 웹 내부 API (api.chzzk.naver.com/service) | 없음 | 팔로워 수, 누적 시청자 등 공식 API에 없는 필드 | **사용 안 함** |
| SOOP | Open API (openapi.sooplive.co.kr) | OAuth, 파트너 승인 | 승인 범위에 따름 | 제휴 후 사용 |
| 유튜브 | YouTube Data API v3 | API 키 | 라이브 동시 시청자(liveStreamingDetails.concurrentViewers), 구독자 수 | 기본 사용, 일일 쿼터 관리 |
| 트위치 | Helix API (Get Streams) | 앱 토큰 | viewer_count, 게임, 언어 | 선택(해외·한국어 방송 비교) |

치지직 웹 내부 API는 여러 비공식 라이브러리가 쓰고 있지만, 네이버는 비공식 API 사용을 허락하지 않았고 비정상 요청 시 계정 보호조치를 할 수 있다고 밝혔다. 서비스의 핵심 데이터를 여기에 걸면 언제든 끊길 수 있으므로 제외한다.

공식 API에 없는 지표(예: 팔로워 추이)는 **스트리머 본인 OAuth 연동**으로 받는다. 본인이 동의한 채널만 상세 지표를 공개한다.

열린 질문: 치지직 공식 라이브 목록의 정확한 응답 필드와 호출 한도는 개발자센터 문서에서 확인해야 한다.

## 수집·집계 아키텍처

```
[치지직 Open API]   [YouTube Data API]   [SOOP Open API (제휴 후)]
         └───────────────┬───────────────┘
                   수집 워커 (1분 주기 폴링)
                         │
                   Supabase DB (스냅샷 → 일 집계)
                         │
                   Next.js 웹 (전 기능 무료 공개)

[타 통계 사이트 · 비공식 API] → 수집 대상에서 제외, 호출하지 않는다
```

수집 워커가 1분마다 각 플랫폼의 라이브 목록을 받아 스냅샷으로 저장한다. 방송이 끝나면 방송 단위 지표를, 매일 새벽에는 일 단위 지표를 계산해 화면은 집계 테이블만 읽는다.

- **방송 감지**: 직전 수집에 없던 채널이 나타나면 방송 시작, 연속 3회 사라지면 종료로 본다
- **주기**: 1분이 기본이며, API 호출 한도에 맞춰 조정한다
- **유튜브**: 쿼터가 작아 등록된 채널만 5~10분 주기로 수집한다
- **공백 처리**: 수집 실패 구간은 0이 아니라 빈 값으로 두고 차트에 표시한다

## 서비스 기능과 화면 설계

모든 화면은 로그인 없이 무료로 열고, 모바일 우선으로 설계한다. 이름과 레이아웃은 자체 기준으로 정해 특정 사이트와 겹치지 않게 한다.

| 화면 | 핵심 내용 | 더 편하게 만드는 포인트 |
| --- | --- | --- |
| 홈 · 지금 라이브 | 전 플랫폼 통합 동시 시청자 순위, 플랫폼·카테고리 필터 | 플랫폼 탭 대신 한 리스트에 통합, 1분 단위 자동 갱신 |
| 스트리머 상세 | 시청자 추이(일·주·월), 평균·최고 시청자, 방송 시간, 카테고리 비중 | 기간 제한 없이 전체 이력 공개, 공유용 이미지 카드 생성 |
| 카테고리 통계 | 카테고리별 총 시청자, 방송 수, 점유율 추이 | "지금 뜨는 카테고리"(전주 대비 증감) 자동 표시 |
| 플랫폼 비교 | 치지직·SOOP·유튜브 총 시청자와 방송 수 추이 | 하나의 차트에 겹쳐 비교 |
| 비교 도구 | 스트리머 2~4명 추이 겹쳐 보기 | URL만으로 비교 결과 공유 |
| 기록실 | 역대·월간 최고 동시 시청자, 최장 방송 | 월별 리캡 자동 생성 |
| 내보내기 | 모든 표 CSV 다운로드, 공개 읽기 API | 연구자·크리에이터가 바로 재활용 |
| 스트리머 대시보드 | 본인 OAuth 연동 시 팔로워 추이 등 상세 지표 | 스트리머가 원할 때만 공개 범위 선택 |

MVP는 앞의 세 화면(지금 라이브, 스트리머 상세, 카테고리 통계)이다.

### 지표 정의

- **동시 시청자**: 수집 시점에 플랫폼 API가 반환한 시청자 수
- **평균 시청자**: 방송 중 수집한 스냅샷의 시청자 수 평균
- **최고 시청자**: 방송 중 스냅샷의 최댓값
- **시청 시간**: 스냅샷 간격(분) × 시청자 수의 합, 단위 시청자·시간
- **점유율**: 같은 시각 해당 카테고리 시청자 ÷ 플랫폼 전체 시청자

## 기술 스택과 DB 스키마

비개발자가 Claude와 함께 유지보수하기 쉬운 조합으로 고른다. 웹과 수집기를 분리해, 웹이 멈춰도 데이터 축적은 계속되게 한다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 웹 | Next.js (App Router) + Tailwind, Vercel 배포 | Claude가 가장 안정적으로 다루는 조합, 무료 티어로 시작 |
| 차트 | Apache ECharts | 시계열·대량 포인트에 강함, 모바일 터치 지원 |
| DB | Supabase Postgres | 무료 티어, 관리 화면 제공, 읽기 API 자동 생성 |
| 수집기 | Node.js 워커, Railway 또는 Fly.io에 상시 실행 | 1분 주기 폴링은 서버리스 크론보다 상시 프로세스가 안정적 |
| 캐시 | Upstash Redis | "지금 라이브" 화면을 DB 조회 없이 응답 |
| 모니터링 | 수집 실패 시 디스코드 웹훅 알림 | 수집 공백을 바로 인지 |

아래 스키마는 출발점이다. 인덱스, 제약조건, 타입 세부는 Claude Code가 구현하며 보완하고 이유를 남긴다.

```sql
-- 채널 마스터: 플랫폼별 채널 1행
create table channels (
  id            bigserial primary key,
  platform      text not null,          -- chzzk | soop | youtube | twitch
  platform_id   text not null,          -- 플랫폼 고유 채널 ID
  name          text not null,
  image_url     text,
  opted_in      boolean default false,  -- 스트리머 OAuth 연동 여부
  unique (platform, platform_id)
);

-- 방송 세션: 방송 1회 = 1행
create table streams (
  id            bigserial primary key,
  channel_id    bigint references channels(id),
  started_at    timestamptz not null,
  ended_at      timestamptz,
  title         text,
  category      text,
  peak_viewers  int,
  avg_viewers   int,
  viewer_hours  numeric
);

-- 스냅샷: 수집 주기마다 방송 중인 채널 1행 (가장 큰 테이블)
create table snapshots (
  stream_id     bigint references streams(id),
  captured_at   timestamptz not null,
  viewers       int not null,
  category      text,
  primary key (stream_id, captured_at)
);

-- 일 단위 집계: 화면 대부분은 이 테이블만 읽는다
create table daily_channel_stats (
  channel_id    bigint references channels(id),
  day           date not null,
  minutes_live  int,
  avg_viewers   int,
  peak_viewers  int,
  viewer_hours  numeric,
  primary key (channel_id, day)
);
```

스냅샷은 30일이 지나면 10분 간격으로 줄여 보관한다. 무료 DB 용량(500MB)을 넘기 전에 유료 플랜이나 별도 시계열 DB로 옮긴다.

## 법적 리스크 체크리스트

가장 큰 리스크는 타 사이트 데이터 사용과 플랫폼 약관 위반이다. 아래를 오픈 전에 모두 확인하고, 출시 전 한 번은 변호사 검토를 받는다. 이 문서는 법률 자문이 아니다.

| 리스크 | 관련 근거 | 대응 |
| --- | --- | --- |
| 타 통계 사이트 DB를 가져다 씀 | 저작권법 데이터베이스제작자 보호, 부정경쟁방지법 성과물 도용·데이터 부정사용 | 타 사이트 데이터·API를 일절 쓰지 않고, 수집 로그로 출처를 증명할 수 있게 보관 |
| 접근 제한 우회 | 정보통신망법 무단 접근 | 로그인·유료 구간·robots 차단 영역에 자동 접근하지 않음 |
| 플랫폼 약관 위반 | 각 플랫폼 개발자 약관 | 공식 API만 사용, 호출 한도 준수, 데이터 재배포 조항 확인 |
| 화면·디자인 유사 | 저작권, 부정경쟁방지법 영업표지 | 자체 디자인 시스템, 서비스명·로고·지표 명칭 독자 개발 |
| 스트리머 개인정보 | 개인정보보호법 | 공개 방송 정보만 수집, 삭제 요청 창구와 처리 기한 공지 |
| 플랫폼 상표·썸네일 | 상표권, 저작권 | 플랫폼명은 설명 용도로만, 썸네일은 원본 URL 링크로 표시하고 저장·가공하지 않음 |

- [ ] 치지직 개발자센터 앱 등록 및 이용약관의 데이터 저장·재배포 조항 확인
- [ ] SOOP Open API 파트너 신청
- [ ] YouTube API 서비스 약관과 쿼터 정책 확인
- [ ] 서비스명 '와글' 상표 검색(키프리스)
- [ ] 개인정보처리방침과 스트리머 삭제 요청 페이지 작성
- [ ] 출시 전 IT 전문 변호사 1회 검토

## 단계별 로드맵

수집을 가장 먼저 시작한다. 통계 서비스의 가치는 쌓인 기간에서 나오므로, 화면보다 하루라도 빨리 데이터를 모으는 것이 핵심이다.

1. **수집 먼저 (1주)**: 치지직 공식 API 키 발급, 수집기 배포, 스냅샷 적재 시작
2. **MVP 화면 (2~3주)**: 지금 라이브, 스트리머 상세, 카테고리 통계
3. **확장 (4~6주)**: 유튜브 추가, 비교 도구, 기록실, CSV 내보내기
4. **SOOP·스트리머 연동 (제휴 승인 후)**: SOOP 수집, 스트리머 OAuth 대시보드
5. **운영**: 광고·후원 수익화, 공개 API, 월간 리캡
